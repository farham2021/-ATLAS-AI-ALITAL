# توسعهٔ پژوهشی ATLAS با فایل‌های ارسالی کاربر

این نسخه، `analysis.txt` &#40;Opportunity V2\.4&#41;، `atlas_professional_monitor.txt`
و `atlas_self_learning.txt` را به ماژول‌های پایتون تبدیل می‌کند و در نقطهٔ
`enrich_result` به هم متصل می‌کند\. فایل `bot.py` تغییر نمی‌کند\.

## جایگذاری

در ریشهٔ مخزن، سه فایل `analysis.py`، `atlas_professional_monitor.py` و
`atlas_self_learning.py` را با فایل‌های همین نسخه قرار دهید\. فایل Workflow
`atlas.yml` را در `.github/workflows/atlas.yml` بگذارید\. سایر فایل‌های پروژه
را تغییر ندهید\. در GitHub Actions ابتدا مرحلهٔ Verify release و سپس لاگ
Opportunity integration را ببینید\.

این تغییر جایگزین بستهٔ قبلی Scheduler نیست؛ Workflow موجود در همین نسخه
پنجرهٔ جبران ۱۸۰ دقیقه‌ای را حفظ می‌کند و فقط بررسی import دو ماژول جدید را
به Verify release اضافه می‌کند\.

## رفتار و محدودیت

- همان ۲۴ رمزارز \+ ۳ فلز فعلی تحلیل می‌شوند\. `build_universe` با ۳۰ ارز متغیر
  خودکار به چرخهٔ اصلی اضافه نشده است\.
- ناظر فقط از OHLCV بستهٔ همان نماد در snapshot فعلی استفاده می‌کند\. دادهٔ
  روزانه/۴ساعتهٔ ناکافی یا کهنه به `UNAVAILABLE` ختم می‌شود\.
- نتیجه در `professional_monitor` داخل payload موجود ذخیره می‌شود؛ BUY/SELL،
  گیت اجرایی، Entry/SL/TP و ارسال تلگرام canonical عوض نمی‌شوند\.
- `research_state=CONFIRMED` فقط برچسب داخلی مدل پژوهشی است؛ مجوز معامله یا
  گزارش عمومی نیست\. `score_not_probability` احتمال برد نیست\.
- فایل یادگیری برای تحلیل نتیجه و پیشنهاد وزن آماده است، اما تنظیم خودکار
  وزن‌ها و نوشتن SQLite/JSON محلی در GitHub Actions فعال نشده است\. برای آن
  ابتدا باید نتیجه‌ها با شناسهٔ یکتا در پایگاه دادهٔ پایدار ثبت و ارزیابی شوند\.
- خبر نامعلوم، «بدون خبر» حساب نمی‌شود و امتیاز خبر نمی‌گیرد\.

## راستی‌آزمایی انجام‌شده

`python -m py_compile` برای سه ماژول موفق شد\. دو آزمون `unittest` برای حفظ
فیلدهای canonical، استفاده از دادهٔ مخصوص هر دارایی و رد دادهٔ کهنه/ناقص
موفق شدند\. یک آزمون ذخیرهٔ موقت نتیجه و توقف یادگیری با نمونهٔ ناکافی نیز
موفق شد\. آزمون زندهٔ بازار/تلگرام و مجموعهٔ pytest پیوست اجرا نشده‌اند\.
